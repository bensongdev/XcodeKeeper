# M4 모니터와 알림 (F3, F4)

PRD 마일스톤 M4. 메모리·스왑 상태와 여유 공간을 메뉴바에서 보여 주고, 공간이 부족하면 알린다.

## 사용자 이야기
나는 8GB/256GB Mac을 쓰는 개발자로서, 메뉴바만 보고 메모리 압박·스왑·여유 공간이 위험한지 알고 싶고,
공간이 부족해지면 무엇을 지우면 되는지 알림으로 받고 싶다. 그래야 빌드가 느려지거나 업데이트가 막히기 전에 정리할 수 있다.

## 수용 기준

### F3 메모리·스왑
- [ ] `SystemMonitor`가 물리 메모리(전체, App, Wired, Compressed), 메모리 압박 단계, 스왑 사용량/전체를 읽는다.
  - App = 내부 페이지 − 비울 수 있는(purgeable) 페이지, Wired = wire, Compressed = 압축기 페이지 (`host_statistics64(HOST_VM_INFO64)`, `hw.memsize`).
  - 압박 단계: `kern.memorystatus_vm_pressure_level` 1→정상, 2→경고, 4→위험. 그 밖의 값은 정상으로 본다.
  - 스왑: `vm.swapusage`(`xsw_usage`)의 used/total.
- [ ] 갱신은 5초 간격. 팝오버가 닫혀 있을 때는 아이콘 색 판단에 필요한 값(메모리 통계, 압박, 스왑)만 읽고, 상위 프로세스는 팝오버가 열려 있을 때만 읽는다.
- [ ] 팝오버가 닫혀 있으면 여유 공간은 60초에 한 번 읽는다(`volumeAvailableCapacityForImportantUsage`는 호출마다 CPU 약 6.6ms, 실측). 아이콘 색이나 메뉴바 숫자가 바뀔 때만 상태를 바꿔 메뉴바를 다시 그리지 않는다.
- [ ] 상위 프로세스 5개: `proc_listallpids` + `proc_pid_rusage`의 `ri_phys_footprint` 내림차순. 읽을 수 없는 프로세스(권한 없음)는 건너뛴다. 종료 기능은 없고, 행을 누르면 활성 모니터를 연다.

### 아이콘 색
- [ ] 빨강: 여유 공간 10GB 미만 또는 메모리 압박 "위험".
- [ ] 노랑: (빨강이 아니고) 여유 공간이 알림 기준(기본 30GB) 미만 또는 스왑 사용량이 스왑 기준(기본 2GB) 초과.
- [ ] 그 밖에는 기본색(템플릿 이미지). 값을 읽지 못한 항목은 판단에서 빼고 기본색 쪽으로 판단한다.

### 팝오버 (폭 320pt)
- [ ] 디스크: 사용/전체 막대, "여유 16.2GB" + 기준 미만이면 "· 업데이트까지 약 14GB 부족"(기준 − 여유, 반올림 GB), "Finder와 같은 기준" 안내.
- [ ] 정리 가능: 마지막 스캔 기준 상위 3개 대상(정리 가능한 대상만, 합계 용량 내림차순)과 용량, 스캔 시각. 스캔한 적이 없으면 "아직 스캔하지 않았습니다". "스캐너 열기" 버튼.
- [ ] 메모리: 압박 단계 배지(정상/경고/위험), App/Wired/Compressed 막대와 수치, 스왑 GB.
- [ ] 상위 프로세스 5개(이름 + 메모리).
- [ ] 하단: 설정, 종료.

### F4 여유 공간 알림과 백그라운드 스캔
- [ ] 여유 공간은 `volumeAvailableCapacityForImportantUsageKey`(이미 M0에서 사용), 전체는 `volumeTotalCapacityKey`로 읽는다.
- [ ] 여유 공간이 기준 미만이면 알림을 보낸다. 제목 "여유 공간이 16.2GB 남았습니다", 본문 "정리 가능: DerivedData 4.2GB, 시뮬레이터 캐시 1.1GB"(마지막 스캔 상위 2개). 스캔 결과가 없으면 "스캐너에서 정리할 항목을 확인하세요".
- [ ] 같은 알림은 24시간에 한 번만 보낸다(마지막 발송 시각을 UserDefaults에 저장). 기준 이상으로 회복해도 쿨다운은 그대로 둔다.
- [ ] 알림 판단은 백그라운드 스캔이 끝날 때 한다(알림 본문에 최신 스캔 결과를 넣기 위해).
- [ ] 알림 권한은 처음 알림을 보내려 할 때 요청한다. 거부되면 조용히 건너뛴다(팝오버의 아이콘 색·문구는 그대로 동작).
- [ ] 알림을 누르면 스캐너 창이 "개발 찌꺼기" 화면으로 열리고, 알림에 적힌 대상의 항목이 모두 선택되어 있다(정리는 여전히 확인 창을 거친다).
- [ ] 백그라운드 스캔: 켜져 있으면(기본 켬) 실행 직후 한 번, 이후 `NSBackgroundActivityScheduler`로 6시간마다(허용 오차 1시간). 저전력 모드이거나 배터리 20% 이하이면 건너뛴다(배터리가 없는 Mac은 배터리 조건 없음).
- [ ] 이미 스캔 중이거나 정리 중이면 백그라운드 스캔을 건너뛴다.

### 설정
- [ ] 여유 공간 알림 기준(GB, 기본 30, 5~200), 스왑 경고 기준(GB, 기본 2, 1~32), 백그라운드 스캔 켜기/끄기, 로그인 시 실행, 메뉴바 숫자 표시.
- [ ] 로그인 시 실행은 `SMAppService.mainApp`의 register/unregister. 실패하면 오류 문구를 설정 창에 그대로 보여 주고, 승인이 필요하면(`requiresApproval`) "시스템 설정 > 일반 > 로그인 항목에서 허용하세요"를 보여 준다.
- [ ] 설정 값은 UserDefaults에 저장한다. UI 테스트·스냅샷에서는 실제 사용자 설정 대신 테스트 전용 저장소를 쓴다.

### 범위 밖 (이번에 하지 않음)
- 설정의 "대상별 포함/제외 토글"(PRD 설정 창 항목, M4 작업 목록에는 없음). 필요하면 별도 작업으로 한다.
- `DispatchSource.makeMemoryPressureSource`: PRD AC가 sysctl 값과 둘 중 하나를 허용하므로 폴링하는 sysctl 값만 쓴다.

## 승인이 필요한 변경 (AGENTS.md: 권한)
| 변경 | 이점 | 비용·위험 |
|---|---|---|
| 알림 권한 (`UNUserNotificationCenter`) | F4 알림. entitlement 불필요(샌드박스 꺼짐) | 첫 알림 때 시스템 권한 창이 뜬다. ad-hoc 서명 앱이라 시스템 설정의 알림 항목이 서명 변경 때 새로 생길 수 있다 |
| 로그인 항목 (`SMAppService.mainApp`) | 로그인 시 자동 실행 | 켜면 "로그인 항목 추가됨" 시스템 알림이 뜬다. ad-hoc 서명이 바뀌면(재빌드) 등록이 무효가 될 수 있다. 기본값은 끔 |
| 설정 값 UserDefaults 저장 | 기준값 유지 | 기존 `showFreeSpaceInMenuBar` 키는 그대로 쓴다(마이그레이션 없음) |
| IOKit(배터리 잔량, `IOPSCopyPowerSourcesInfo`) | 배터리 20% 조건 | 시스템 프레임워크, 서드파티 아님 |

## 위험 요소
- 다른 프로세스 정보(`proc_pid_rusage`)는 같은 사용자 프로세스만 읽힌다 → 상위 5개는 "읽을 수 있는 프로세스 중" 상위다. 이름은 보고서·스크린샷에 실제 값이 남지 않도록 테스트에서는 가짜 값만 쓴다.
- 알림을 누르면 주의(caution) 대상의 항목도 선택될 수 있다 → 정리는 확인 창과 휴지통 이동을 거치므로 되돌릴 수 있다.
- 유휴 CPU 0.5% 기준: 5초 폴링은 C API 몇 번 호출이며, 상위 프로세스 열거는 팝오버가 열렸을 때만 한다.
- 실제 알림 표시·클릭, 로그인 항목 등록은 시스템 UI라 자동 테스트로 확인할 수 없다 → 수동 확인 또는 NOT RUN.

## 실측 (2026-11-19, Release 빌드, 이 Mac)
- 앱 크기: 1.9MB (기준 10MB 이하)
- 유휴 메모리: phys_footprint 16MB (기준 40MB 이하)
- 유휴 CPU: 300초 동안 0.19초 = 0.06% (기준 0.5% 이하). 여유 공간을 5초마다 읽던 첫 구현은 0.52~0.65%로 기준을 넘어 60초로 바꿨다.
- 실제 앱 실행에서 `AppLifecycle` 수정자가 environment 바깥에 있어 실행 직후 크래시 → 순서를 고쳤다(단위 테스트·스냅샷은 App 장면을 그리지 않아 잡지 못함).

## 버그 수정: 팝오버 버튼이 창을 열어도 팝오버가 남음 (2026-11-19, 사용자 보고)
- [ ] 팝오버의 "설정…"을 누르면 팝오버가 닫히고 설정 창이 앞에 열린다.
- [ ] 팝오버의 "스캐너 열기"를 누르면 팝오버가 닫히고 스캐너 창이 앞에 열린다.
- [ ] 닫힌 뒤 메뉴바 아이콘을 한 번 누르면 팝오버가 다시 열린다(두 번 눌러야 하는 상태가 되지 않는다).
- 테스트: UI 테스트 `testPopoverButtonsClosePopover`(CI, 로컬은 NOT RUN). 팝오버 닫힘·창 열림·재열림을 assertion으로 확인하고 `05-after-open-scanner`, `06-after-open-settings`를 찍는다.

## 개선: 이미 열린 창을 팝오버에서 다시 열면 그 창으로 포커스 (2026-11-19, 사용자 요청)
- [ ] 스캐너 창이나 설정 창이 이미 열려 있을 때(다른 창 뒤에 있거나 최소화된 경우 포함) 팝오버에서 해당 버튼을 누르면 그 창이 맨 앞의 키 창이 된다.
- [ ] 같은 창이 새로 하나 더 생기지 않는다.
- [ ] 알림을 눌러 스캐너 창을 열 때도 같은 방식으로 맨 앞에 온다.
- 테스트: UI 테스트 `testPopoverButtonsFocusAlreadyOpenWindow`(CI, 로컬은 NOT RUN). 두 창을 모두 연 뒤 팝오버 버튼마다 맨 앞 창(`app.windows.firstMatch`)과 창 개수를 assertion으로 확인하고 `07-focus-scanner`, `08-focus-settings`를 찍는다.
